## Tabs are the user's property

- Name the session with the first tab (`tab_open {session}`, or `browser.nameSession()` in `js`; short, emoji-prefixed). Agent-created tabs go into a Chrome tab group with that name, open in the background, and are muted until the user looks at them.
- To work in the foreground tab, call `tab_claim {active:true}`. To find a different user tab, call `tab_list {user:true, query:"…"}` and pass its `tabId` to `tab_claim`. User-tab discovery returns up to 20 recent matches by default; `limit` can raise this to 100. You can also claim by `url` (exact or prefix) and/or `title` (substring) when the match is unique (`claim_ambiguous` lists candidates). When the user means one specific tab, copy its current URL/title into exact `expectedUrl`/`expectedTitle` guards. Claimed user tabs are never moved into the agent group or closed by finalize. `tab_list` shows each session tab's string page `id`, numeric `tabId`, `origin`, and `state`. If a connected older extension reports `pending:true`, use the numeric `tabId` to find the page handle on a later call.
- A browser tab must be explicitly opened or claimed before use. Its page handle is the Chrome tab id encoded as a string and stays stable across navigation; a closed tab's handle becomes stale. An unknown page id is rejected rather than silently adopted. `tab_release` keeps any controlled tab open and gives up control; for agent-created tabs it also removes the group and unmutes them. `tab_close` closes any controlled tab, including a claimed user tab. The JavaScript equivalents are `tab.release()` and `tab.close()`. To close several user tabs, use `tab_close {tabIds:[...]}` or `browser.user.closeTabs([tabId1, tabId2])`; this does not claim them first and returns `closed` and `failed` ids. Claimed session tabs still use `tab_close {tab}`. `tab_claim` returns both the string session page handle (`tab`) and numeric Chrome `tabId`.
- Popups and links the agent opens are captured into the same session.
- Finish with `session_finalize`. Keep a tab only when the user needs the live page: `deliverable` leaves the group and stays open; `handoff` stays in the group for a later turn. Everything else the agent opened is closed. The result reports `closed`, `kept`, and any `failed` tabs. Failed tabs retain their lease for retry. Finalize is the last browser action of a turn when cleanup succeeds: afterwards every `Tab` handle is dead (`page_released`), and a kept tab is the user's again — a later turn claims it back from `tab_list {user:true}`. The stdio launcher finalizes its session on disconnect; direct HTTP clients should call `session_finalize` or `DELETE /session`. An idle browser session is also finalized after an hour.
- Keep the browser in the background by default; `(await browser.capabilities.get('visibility')).set(true)` in `js` only when the user wants to watch.

- The cursor overlay is owned by the runtime, not the page: it is only shown in the tab the user is looking at (active tab of a non-minimized window), keeps its position across navigations, and disappears when the tab leaves the session (finalize/release). In unobserved tabs actions do not animate or wait for the cursor.
- The debugger attachment to a tab is kept for the whole session and released by finalize. If the user cancels it from Chrome's debugging bar, the next action re-attaches once automatically; no per-action health check is performed.
